# 代码注释策略

审查、补全、精简或重写代码注释时，按下面这套规则判定。

## 核心原则

1. **默认怀疑**：每条注释都要能回答“它承载了签名、类型或代码里看不出的什么信息”。答不上来就删；能证明有用才留。
2. **注释不是第二份实现**：能从签名读出的（`Option` 何时为 `None`、返回值元组）、能从紧邻代码读出的（轮询间隔、分支顺序、循环结构）不写。写下来就会漂移。
3. **只写读者需要且代码说不出的**：失败/panic 条件、前置条件、可观察的怪癖、领域硬约束（单位、路径、顺序、生命周期）、非显然的“为什么”。
4. **可验证**：每条断言（阈值、单位、默认值、顺序、返回值、错误条件）回代码核对；绝对断言（总是/唯一/从不/一律/恒为）必须找反例。
5. **公开文档不写内部行话**：不写仓库拓扑、依赖规约、变更史、审阅口吻，也不写与本 crate 无关的跨 crate 关系；理解本 crate 职责或公开 API 所必需的相邻层关系可以写一句。
6. **只改注释**：不顺手改代码、不重构、不提交；发现的代码问题单独报告。
7. **项目既有约定优先**：仓库的 AGENTS.md、既有注释风格、rustdoc 链接习惯优先于本 skill；不要引入并存的第二套约定。

## 分层与边界

- **后端/库层**：描述数据与契约本身，不描述消费者行为（“由前端展示”“由调用方落盘”改写成事实）。
- **trait 与 impl**：契约在 trait；实现处放松，只写实现特有的具体差异。
- **跨边界 SDK（插件、FFI、wasm）**：对外文档不透露已被 SDK 封装的机制（ABI、线协议、返回码、宿主函数名）；保留作者必须知道的 API 形状、路径、可观察语义与坑（`/tmp`、`/assets`、共享流位置、构建目标）。
- **私有项**：不渲染的实现说明（ABI、unsafe extern 块、内存布局）可以留给维护者；只有公开文档受上述约束。
- 不写仓库拓扑与全局事实。

## 该写什么

- **契约**：失败条件、错误分支、panic 条件、前置条件、调用方必须保证的事。
- **可观察的怪癖**：宽限期、超限走状态码而不走错误、共享游标、按块读取上限、某路径只读不写。
- **领域硬约束**：单位（秒/字节）、默认值、路径限制（`/tmp`、`/assets`）、生命周期与顺序要求。
- **为什么**：非显然选择、绕过特定 bug 的 workaround、看不出取舍的动机。
- **出处**（有条件）：能解释非显然行为的来源说明（“移植自 X”）；装饰性的“与 X 一致”等价断言不写。
- **既有标记**：项目已有的 `// SAFETY:`、`// PERF:` 等保留；不要新造 `// CONTEXT:` 之类的约定。

## 结构

### 摘要句

首行一句话，第三人称动词开头（返回/创建/加载/判断/渲染），不带长括注，不塞返回值；run-on 拆句。

### rustdoc 分节

- `# Errors`：返回 `Result` 且错误条件值得说明时用。
- `# Panics`：存在可预见且值得记录的 panic 条件时用；必须能指出触发它的代码分支，指不出就删。
- `# Safety`：`unsafe` API 需要记录调用者必须满足的安全契约时用。
- `# Examples`：示例能显著帮助使用时用；可运行示例优于伪代码。
- 内部 fn、纯粹的 IO/serde 透传不加 `# Errors` 样板。

### crate / 模块 doc

- crate doc：这层是什么、与相邻层什么关系，一句即可；可用极短列表概括关键模块职责（不是抄 `pub mod` 声明清单），不写架构规约。
- 模块 doc：可列直接子项，无序列表，一项一行；只列直接子项，不列孙辈；不写“值得一看/值得注意”这类评价词；子模块已说明的不重复列。
- 每个 crate 有 `//!`；模块职责不显然时加 `//!`。

```rust
//! Tuack-NG 后端：题目开发的核心业务逻辑。
//!
//! - [`mod@test`] / [`dmk`]：评测与数据生成会话
//! - [`ren`] / [`dump`]：渲染与导出契约
```

### 类型 / 字段 doc

- 字段 doc 只写看不出的语义：单位、默认值、与其它字段的耦合、不变式；不复述字段名。
- “必填/可选”能由类型看出的（`String` 与 `Option<String>`、`#[serde(default)]` 的对照）删掉。
- 解释泛型包装器携带什么时（如 `Spanned<T>` 的可选 span）可以写。

### 链接

- workspace 类型用 `` [`Type`] ``；跨 crate、有歧义、宏用全限定目标：`` [`mod@test`] ``、`` [`processor!`](crate::processor!) ``。
- 公开文档只链公开项；std 类型不必加链接。
- 加链接后必须让 `cargo doc` 保持 0 warning。

## 语言与格式

- 注释语言与仓库一致；类型名、术语、错误消息、命令、路径按原样保留，不主动换同义词，不把多个概念压成一个概括词；术语用准确的技术表达，不为顺口换成含糊说法。
- 代码注释内符号用 ASCII：`->`、`<-`、`=>`，不用 `→`、`⇒`；中文引号用「」；不用 emoji。
- 注释中不得滥用破折号 `——`，请使用 `。`/`，`/`：`/`（）` 来代替。
- 行注释用 `//`、`///`、`//!`，不用 `/* */`。
- 注释行显示宽度（CJK 计 2）不超过 96 列，在自然断点折行。拆成多行 `///` 时保留标点。rustdoc 会把相邻行并成一段，丢了冒号或逗号就粘连。
- 短短语型注释（字段、类型、变体）末尾不加 `。`；完整句子（模块头、带从句的函数 doc）可以加。
- 不用“某些/各种/等”含糊词，具名到具体变体或类型；不用“现在/原来/改成”的变更史。
- 无动机的 TODO 删除；要留就写清动机与触发条件。

## 坏味道清单

按严重度排列，先修事实错误。判定基准是删除测试：删掉后读者是否真的会失去信息。删的是提示语、过渡语与复述；条件、否定、因果、主次不能跟着删。

### 事实错误

注释与当前代码矛盾：阈值、单位、默认值、分支顺序、错误条件、返回值、panic 条件、示例。

处理：逐个回代码核对。同类错误常成对出现（同一说法在类型 doc、方法 doc、另一个文件各有一份），修一处后全仓搜同句。

示例：

```rust
/// 运行时间，TLE/MLE 时为 `None`。
pub time: Option<Duration>,
/// 峰值内存（字节），TLE/MLE 时为 `None`。
pub memory: Option<u64>,

// ...

if elapsed > time_limit {
    return Ok((RunStatus::TimeLimitExceeded, None, Some(final_peak)));
}
if final_peak > memory_limit {
    return Ok((RunStatus::MemoryLimitExceeded, None, Some(final_peak)));
}

// 等待子进程失败（InternalError）
Err(e) => (RunStatus::InternalError(e.into()), None, None),
```

改写：

```rust
/// 峰值内存（字节）；运行器内部错误时为 `None`。
pub memory: Option<u64>,
```

说明：`time` 在 TLE/MLE 时确实是 `None`；`memory` 在 TLE/MLE 时带回杀进程前的峰值，只有等待子进程失败才是 `None`。

### 复述近处子项

模块头把紧邻的 `pub mod` 抄一遍；类型 doc 把字段/变体逐个抄一遍；doc 复述方法名。

处理：删。模块 doc 若要列，按「模块 doc」规则只列直接子项。

示例：

```rust
//! 处理器插件实现 [`Processor`]，渲染器插件实现 [`Renderer`]，导出器插件实现
//! [`Dumper`]；分别用 [`processor`] / [`renderer`] / [`dumper`] 宏注册为
//! extism 导出函数，JSON 编解码（字节载荷走 msgpack）、内存与错误处理均由 SDK 接管。
```

改写：

```rust
//! - [`Processor`] / [`processor!`](crate::processor!)：处理题目 AST
//! - [`Renderer`] / [`renderer!`](crate::renderer!)：渲染题面
//! - [`Dumper`] / [`dumper!`](crate::dumper!)：导出到评测系统
```

说明：crate doc 不复述各模块的职责与注册方式，列表指过去即可。

### 机制写进契约

把实现细节当接口承诺：轮询间隔、循环结构、内存分配、具体函数调用、落盘方式、临时文件命名。

处理：删机制，留可观察后果。只有会改变调用方行为的实现细节（例如宽限期会让刚过时限的进程判为成功）才以“可观察语义”写。

示例：

```rust
/// 监督一个已 spawn 的子进程，返回 (结束状态，用时，峰值内存)……
///
/// 与 `child.wait()` 并发，每 20ms 采样一次内存；命中时限或内存上限即杀掉进程并返回
/// `TimeLimitExceeded` / `MemoryLimitExceeded`……

// 原文真的太长了，就不展示了
```

改写：

```rust
/// 监督一个已 spawn 的子进程，超出时限或内存上限即杀掉；时限判定留 200ms 宽限。
///
/// # Errors
///
/// 取不到子进程 PID（进程已退出）时返回 `Err`；TLE/MLE 经 [`RunStatus`] 返回，不算错误。
```

说明：删掉签名已给的返回值元组、20ms 采样与控制流细节；保留看不出的信息：越限即杀、200ms 宽限、错误归属与异常情况。

### 仓库内部词汇泄漏

`前端`、`后端`、`消费方`、`gctx`、`msg_*`、`crates/...` 路径、内部 crate 名等说法，对公开文档读者无意义。`调用方` 也不应被用来泛指外部职责的承接者；但用于说明 API 的必要入口、前置条件或调用约束时可以保留。

处理：改成对数据与契约本身的正面描述。

示例：

```rust
/// 前端展示状态 (评测状态 + 编译失败)
```

改写：

```rust
/// 展示状态：由 [`TestCaseStatus`] 映射而来，另加编译失败（CE）
```

说明：删掉「前端」；说明状态从哪来、额外包含什么。

### 教调用方做事

doc 写调用方拿到结果后该做什么（“由调用方决定如何输出”“由调用方统一处理”“调用方自行检查”），或把调用方的工作流程当成本条目的内容。

处理：只写本条目自身的行为与返回值，不规定结果的展示、转发或业务处置方式。注意区分前置条件与后续契约：调用前须先 X 属于前置条件；API 强制要求的后续操作与生命周期约束也属于契约；拿到结果后由外部自行决定如何展示或用于业务处理，则不属于。

示例：

```rust
/// 编译 Validator，失败时返回错误，由调用方决定如何输出
```

改写：

```rust
/// 编译 [`Validator`]，失败时返回错误。
```

说明：函数只负责编译；“如何输出”是调用方的事，不写进这里的文档。

### 不可证伪断言

`全仓唯一`、`总是`、`从不`、`唯一入口`、`一定`、`必然`、`恒为`。

处理：回代码验证；不能证明就删，或改成有边界的条件句。

示例：

```rust
//! - dumper 不访问配置对象；用户资源（data/sample/down/checker）一律经 `AssetProvider` 获取。
```

改写：

```rust
//! 资源经 [`AssetProvider`] 注入，不直接接触配置。
```

说明：去掉「一律」这类覆盖全量的量词；只写实际的资源来源。

### 冗长

超过三段；摘要句 run-on；括号套括号；首行塞返回值和多重括注。

处理：摘要一句话；正文按“是什么 / 何时失败 / 为什么”分段；删掉能从代码看出的解释。

示例：

```rust
//! 渲染抽象
//!
//! 渲染指：以数据变换为核心的操作，旨在将原文档转换为各种形式。
//!
//! - `RenderDocument` 是不可变输入，`Renderer::render` 产出 `Vec<OutputFile>`。
//! - 渲染器允许的，可忽略不计的副作用：写自己的临时目录、调用外部命令（如 typst）。
//! - 渲染器禁止：访问 `gctx()`（获取资源可能除外）、直接读取用户资源（除非经 `AssetProvider`）、写最终输出目录。
```

改写：

```rust
//! 渲染抽象，与 dump 同构。
//!
//! [`RenderDocument`] 是不可变输入，[`Renderer::render`] 产出 [`OutputFile`] 列表。实现可
//! 进行渲染所必需的 I/O（写临时目录、调用外部命令），但资源均经 [`AssetProvider`] 取得，
//! 且不写最终输出目录。
```

说明：删掉定义句与逐条清单，压成一段只讲边界。

### 重复

同一事实在 crate doc、模块 doc、类型 doc、字段 doc、行内出现两次以上。

处理：只保留最靠近读者、最权威的一处；其他位置删掉或改为链接。

示例：

```rust
// (模块头)
//! - `DumpDocument` 是不可变输入（day 级纯数据），`Dumper::dump` 产出 `(Vec<OutputFile>, Vec<String>)`——
//!   导出产物文件与导出过程中的面向用户警告（如平台限制、编译失败提示），由调用方负责展示。

// (trait doc)
/// 导出器：`DumpDocument -> (产物文件列表，导出警告)`。
```

改写：

```rust
/// 导出器：把 [`DumpDocument`] 导出为产物文件与警告文本。
```

说明：返回类型只在 trait doc 保留一处，模块头不再复述。

### 变更史、审阅口吻与装饰

“现在”“原来”“改成”、第一人称、“这里应该”、含糊词（某些/各种/等）、emoji、`// ---- 横幅 ----`、`/* */` 块注释。

处理：删；含糊词换成具体类型/变体；块注释改逐行 `//`；不新增装饰性横幅。

示例：

```rust
/*
已知在行中有 $$, {{ }} 时，不会告警没有句号，对于 {{ }}，也不会保留空格。
但是由于这两种情况复杂（比如：模板语句可能不需要句号，$$ 可能后面会是 ;；. ；），实际上没有什么妥善方法检查，暂时忽略。
*/
```

改写：

```rust
// 已知在行中有 $$, {{ }} 时，不会告警没有句号，对于 {{ }}，也不会保留空格。
// 但是由于这两种情况复杂（比如：模板语句可能不需要句号，$$ 可能后面会是 ;；. ；），实际上没有什么妥善方法检查，暂时忽略。
```

说明：块注释改逐行 `//`，内容逐字保留。

### 契约缺失

非显然的 panic、错误条件、前置条件没写；散文提到本 workspace 类型却没有链接。

处理：补到对应分节或句子里；加 `[...]` 链接（见「链接」）。

示例：

```rust
/// 做必要的准备工作
fn prepare(&mut self) -> Result<()>;
```

改写：

```rust
/// 运行前准备（如编译）；须先于 `execute` 调用
///
/// # Errors
///
/// 准备失败时返回 `Err`：临时目录创建或源文件拷贝失败、编译命令构造失败、
/// 编译器进程无法启动，或编译以非零码退出（编译错误输出在错误消息里）。
fn prepare(&mut self) -> Result<()>;
```

说明：补上调用顺序与错误条件；原先那句只是复述方法名。

### 跨 crate 与仓库拓扑

crate/模块 doc 写“不依赖 crate X”“不使用 Y 的 gctx()”“由 Z 调用”。

处理：删。这是架构文档的内容，在 rustdoc 里既不可解析，又必然漂移。

示例：

```rust
//! 自建 Markdown AST。
//!
//! 结构与 markdown-ppp 的 AST 形状对齐，便于迁移渲染器与 Visitor；
```

改写：

```rust
//! Markdown AST 节点定义。
//!
//! 每个节点通过 [`crate::span::Spanned`] 携带可选的源码位置。
```

说明：删掉「自建」与对其他实现的形状对齐断言；模块 doc 只说本模块是什么。

### 全局性事实陈述

“本 crate 几乎全同步”“唯一异步点是 X”“目前只有 N 处”“全仓没有 Y”。

处理：用删除测试：读者看签名或模块清单就能知道，或该陈述不改变任何用法，就删。`唯一/只有/几乎全` 还是绝对断言，会腐烂。

示例：

```rust
//! 全仓库唯一的异步点：同步调用方经 [`ProcessSupervisor::supervise_blocking`] 进入
//! [`monitor_runtime`]，由 `tokio::select!` 同时等待子进程退出与内存采样，以便在确认
//! 超限的瞬间终止进程。
```

改写：

```rust
//! 子进程资源监控。同步调用方经 [`ProcessSupervisor::supervise_blocking`] 进入监视器
//! runtime，监视器并发等待子进程退出与内存采样。
```

说明：删掉「全仓库唯一」的定性；读者打开条目就能看出这里是不是异步。

> 可能会有疑惑：`调用方` 不是在「教调用方做事」吗？
>
> 但答案是否定的，因为这确实是调用方需要知道的东西，调用方不知道用什么函数就会完蛋。
>
### “是 X，不是 Y”式定义

如 `（支持引号与转义，非按空白简单切分）`。读者不需要知道它不是谁。

处理：只留正面定义。

示例：

```rust
/// 只读资源挂载点：各插件工厂把包的 `asset_dir` 挂到 `with_allowed_path(..., "/assets")`。
///
/// 它不是工作区内的路径：`host_get_path`、`run_command` 的 `cwd` 与 `asset_copy` 的目标都不接受。
```

改写：

```rust
/// 只读资源挂载点：各插件工厂把包的 `asset_dir` 挂到 `with_allowed_path(..., "/assets")`。
///
/// 该挂载点位于工作区之外，`host_get_path`、`run_command` 的 `cwd` 与 `asset_copy` 的目标都不接受。
```

说明：用正面陈述说明它在哪里，不先让读者知道它「不是什么」。

### 括号重述

括号里重复前文或举例，如 `（支持 A、B、C）`。

处理：删括号；确有必要的信息并入正文。

示例：

```rust
/// 命令串存在未闭合的引号（shellwords 解析失败），或拆分结果为空时返回 `Err`。
```

改写：

```rust
/// shellwords 解析失败，或拆分结果为空时返回 `Err`。
```

说明：括号是对前文的重述，删掉不丢条件；错误分支与返回类型原样保留。

### trait 契约与实现说明错位

契约（何时 panic、返回什么错误、前置条件）应写在 trait 方法上；实现处不逐字重复。

处理：契约上移到 trait；实现处只写实现特有的、朴素一到三行说明（如“仅 Linux”“不支持交互题时会 panic”），不套 rustdoc 分节。实现特有情况要写，但不必遵循 rustdoc 结构。

示例：

```rust
// trait 只有一句，impl 没有说明

/// 设置交互
fn set_interactive(&mut self, grader_file: &Path, header_file: &Path) -> Result<()>;
```

改写：

```rust
// trait
/// 启用交互模式：指定 grader 与头文件，须在 `prepare` 前调用
///
/// # Panics
///
/// 运行器不支持交互式题目（[`RunnerManifest::interactive`] 为 `false`）时
/// panic；调用方须先经 [`Runner::manifest`] 确认支持。
fn set_interactive(&mut self, grader_file: &Path, header_file: &Path) -> Result<()>;

// impl
/// 通用运行器不支持交互：模板无法链接交互库
fn set_interactive(&mut self, _grader_file: &Path, _header_file: &Path) -> Result<()>;
```

说明：契约放 trait；实现处只留一句实现特有的说明，不重复 `# Panics`。
